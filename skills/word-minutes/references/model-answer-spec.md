# 模範解答から抽出した書式仕様

議事録の模範.docx から抽出した、インデント・書式・構造の正確な仕様。
generate_minutes.py および validate_minutes.py で使用する。

---

## 文書全体構造

```
[基本情報テーブル]     ← 5行2列（日時/場所/タイトル/出席者/使用資料）
[空行]
<アジェンダ>           ← セクション見出し（太字）
  1. アジェンダ項目1   ← 連番付き
  2. アジェンダ項目2
[空行]
<決定事項>             ← セクション見出し（太字）
[決定事項テーブル]     ← No + 決定事項（2列）
[空行]
<ToDos>                ← セクション見出し（太字）
[ToDoテーブル]         ← No + To Do + 担当者 + 期限（4列）
[空行]
<議事詳細>             ← セクション見出し（太字）
  [議事内容]           ← インデント階層で構造化
[空行]
<次回ミーティング>     ← セクション見出し（太字）
  日時/場所/出席者
[空行]
以上
```

## 基本情報テーブル

| 行 | 左セル | 右セル | 備考 |
|----|--------|--------|------|
| 0 | 日時 | YYYY年MM月DD日（X曜日） HH:MM～HH:MM | |
| 1 | 場所 | 会場名 | |
| 2 | ミーティング・タイトル | 会議名 | |
| 3 | 出席者\n（敬称略・順不同） | {組織名}）\tメンバー名, ... | 作成者名の後ろに（記） |
| 4 | 使用資料 | 資料名 | |

テーブル仕様:
- 幅: 10059 twips
- グリッド: 左列 3579 twips + 右列 6480 twips
- 罫線: single, 6pt (#999999)
- 左セル: pct20 灰色シェーディング, 中央揃え
- セルマージン: 左右99 twips

## 議事詳細のビュレット（箇条書き記号）

議事詳細の発言には Word ナンバリング（numPr）によるビュレットを付与する。
generate_minutes.py は numId=100 を動的に作成し、3段階のインデントを実現する。

| ilvl | ビュレット文字 | フォント | 対象 |
|------|---------------|----------|------|
| 0 | ● (U+F0B7) | Symbol | level 1（新しい論点・発言） |
| 1 | → (U+F0E0) | Wingdings | level 2（回答・反応） |
| 2 | → (U+F0E0) | Wingdings | level 3（さらなる回答・反応、より深いインデント） |

ビュレットの indent 定義は numPr 側に持つが、段落の left_indent / first_line_indent で
上書きするため、実際の位置は下記「インデント階層」の値が優先される。

## ToDo/決定事項タグ

議事詳細の発言末尾に付与するタグ:

- **形式**: `<ToDo#N （担当者）>` または `<決定事項#N>`
- **太字**: True
- **色**: 赤 (#FF0000)
- **位置**: 発言テキストの末尾、同一段落内
- **番号**: テーブルの連番と対応

模範例:
```
了解した。（UM小山）<ToDo#1 （UM小山） >
了解した。（ACN立川）<ToDo#2 （ACN立川）>
...インタビュー対象を中村様に変更してほしい。（UM小山）<決定事項#1>
```

## 出席者の特殊マーカー

| マーカー | 意味 | 例 |
|---------|------|-----|
| `（記）` | 議事録作成者 | `横川（記）` |
| `(※)` | リモート参加者 | `田中(※)` |

出席者欄には必ず1名「（記）」を付与する。

---

## 発言者表記

- 形式: `（組織略称 名前）` — 例: `（ACN立川）` `（UM小山）`
- 敬称: 基本不要（自組織メンバー）。クライアント側は「様」を場合によって使用
- 初回に組織正式名と略称を対応: `ユニバーサルモバイル(以下UM)）`
- 複数発言者: `（ACN立川、OM吉田）`

---

## 文書末尾

- 「以上」で終わる
- インデントなし、太字なし
